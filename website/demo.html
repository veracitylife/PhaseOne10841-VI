Walkthrough

Eleven building blocks of Agent EDR

Each step shows a defensive control that sits outside the model.

1

Gateway proxy

Agents and SDKs point at PhaseOne10841 instead of the upstream LLM. The OpenAI-compatible gateway applies middleware on chat completions, tool calls, and peer messages before anything reaches tools or models.

  • Single control plane for LangChain, CrewAI, OpenAI SDK, and adapters
  • Policy, scanners, and recording run on every request path
  • Upstream stays configurable (OpenAI, Ollama, OpenRouter, mock)

POST /v1/chat/completions proxied
tool_call · http_fetch policy check
a2a · peer message scanned 
Agents / SDKs ──► Gateway
                    ├─ policy YAML
                    ├─ injection scanner
                    └─ recorder → Postgres
2

Policy YAML

Operators express intent in YAML: domain default-deny, shell deny-by-default, filesystem roots, MCP allowlists, secret egress rules, and approval timeouts. Invalid or disallowed keys are rejected on save.

  • Destructive tools route to human approval
  • Validated save path with previous-version backup
  • Detection rules live alongside policy in versioned files
policy.yaml · editor 
domains:
  default: deny
  allow:
    - api.internal.example
shell:
  default: deny
tools:
  destructive: require_approval
mcp:
  allowlist:
    - docs-search
secret_egress: block
approval:
  timeout_seconds: 900
3

MFA dashboard

Admins sign in with email OTP. The console surfaces incidents, session replay, pending approvals, policy, agents, canaries, SIEM export, and lab status- with lightweight RBAC (admin vs viewer).

  • Email one-time passcodes; rate-limited OTP requests
  • Admin audit log for login, approve/deny, policy save, export
  • Ops views for health, retention, and rate-limit notes

4

Session replay

Every gated interaction is recorded to Postgres. Deep session replay lets operators reconstruct the chain of prompts, tool decisions, policy hits, and approvals-useful for incident review and compliance.

  • Event store with session continuity
  • Redaction for secrets on egress paths
  • Export-friendly records for SOC handoff
replay · session_7f3a
  • chat.completion agent → gateway → upstream
  • tool.evaluate http_fetch · domain allow
  • policy.hit secret_egress · redacted
  • approval.resolve human · allow · noted
5

Canaries

Harmless marker files act as tripwires. If an agent or process touches them unexpectedly, PhaseOne10841 raises a high-severity signal-without storing real secrets in the markers.

  • List, safely rotate, and review last trigger from the dashboard
  • Optional webhook alert on canary events
  • Complements filesystem root policy

.phaseone-canary-a quiet
.phaseone-canary-b touched
last rotate 2h ago
6

A2A firewall

Agent-to-agent peer messages pass through trust levels and injection scanning. Operators can list and set trust from the admin API and settings UI so multi-agent coordination does not bypass the gateway.

  • Trust tiers for known vs untrusted peers
  • Injection patterns scanned on peer content
  • Events recorded like any other gated path
a2a · trust map
agent.planner trusted
agent.researcher limited
peer.unknown deny / scan
7

Human approval

When policy marks a tool as destructive, the gateway holds the action until a human resolves it-with risk, reason, expiry, and notes. Timeouts expire pending requests safely rather than auto-approving.

  • Approve or deny from the MFA dashboard
  • Audit trail of every resolution
  • Optional alert on approval timeout

SIEM export

Feed your existing SOC stack. PhaseOne10841 emits ECS-style JSONL for download and optional webhook sinks for canary, injection-blocked, and approval-timeout events-plus Prometheus metrics on the gateway.

  • /metrics for operational visibility

  • Stub services for safe practice runs
  • Labeled fixtures exercise scanners and rules
  • Smoke tests after docker compose up

10

Automated Gatekeeper

YAML playbooks automate defense responses in a Sense → Decide → Act → Learn loop. Tiered actions (observe, contain, harden) let operators respond proportionally. High-impact changes require human confirmation-enforcement stays deterministic.

  • Dry-run mode - observe without mutations until ready
  • Runtime overrides - temporary policy (deny tool, tighten rate limit) with auto-expiration
  • LLM advisor - optional suggestions via OpenRouter / Ollama; LLM advises, playbooks decide
  • Human confirmation - harden-tier actions wait for admin approval
gatekeeper · playbooks 
id: canary-response
tier: contain
match:
  event_type: canary.trigger
  severity: [high, critical]
actions:
  - type: emit_alert
  - type: force_approval
    params:
      tools: ["*"]
      duration_ms: 300000
mode dry-run (safe)
pending 1 confirmation
11

Operator CLI & GUI

  • Recommended first run - onboard → compose up → health → smoke → gui
  • Gatekeeper commands - status, dry-run, llm-check, confirm/deny
  • Local GUI - browser-based interface with guidance panel and examples
